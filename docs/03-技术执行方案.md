## 二、系统架构

### 2.1 总体架构

```
用户 → Nginx (443) → Frontend (3000)
                   → Backend API (8080) → HAProxy → OneAPI Blue (3001) → Provider APIs
                                                 → OneAPI Green (3002)
                   监控层: Prometheus (9090) → Grafana (3030)
```

### 2.2 分层职责

| 层 | 组件 | 职责 |
|----|------|------|
| 用户前端 | Next.js 15 App Router | 注册/登录、API Key 管理、充值、用量仪表盘、模型文档 |
| 后端网关 | Go 1.21+ (Gin) | 业务逻辑：认证、配额检查、支付回调、管理 API、审计日志 |
| API 代理 | OneAPI（双实例蓝绿） | 多渠道转发、限流、计量、Key 分发、OpenAI 兼容端点 |
| 负载均衡 | HAProxy | 蓝绿流量切换、健康检查、加权路由 |
| 反向代理 | Nginx | HTTPS 终结、静态文件服务、路径路由 |
| 数据库 | SQLite (WAL) | 用户数据、用量记录、配置持久化 |
| 监控 | Prometheus + Grafana | 指标收集、可视化仪表盘、告警 |
| 支付 | NOWPayments | 非托管加密网关（USDT TRC-20），自动回调确认 |

### 3.2 核心数据模型

```go
// User — 用户
type User struct {
    ID           int64     `json:"id"`
    Email        string    `json:"email"`        // 唯一
    PasswordHash string    `json:"-"`            // bcrypt
    DisplayName  string    `json:"display_name"`
    Balance      float64   `json:"balance"`      // 美元余额
    Role         string    `json:"role"`         // user / admin
    Status       string    `json:"status"`       // active / frozen
    CreatedAt    time.Time `json:"created_at"`
    UpdatedAt    time.Time `json:"updated_at"`
}

// ApiKey — 用户访问密钥
type ApiKey struct {
    ID        int64     `json:"id"`
    UserID    int64     `json:"user_id"`
    Key       string    `json:"key"`        // sk-xxx 格式
    Name      string    `json:"name"`       // 用户自定义名称
    Status    string    `json:"status"`     // active / revoked
    Quota     int64     `json:"quota"`      // token 配额上限（0 = 无限制）
    Used      int64     `json:"used"`       // 已用量
    IPWhitelist []string `json:"ip_whitelist"` // IP 白名单
    ExpiresAt *time.Time `json:"expires_at"`
    CreatedAt time.Time `json:"created_at"`
}

// UsageRecord — 用量记录
type UsageRecord struct {
    ID        int64     `json:"id"`
    UserID    int64     `json:"user_id"`
    ApiKeyID  int64     `json:"api_key_id"`
    Model     string    `json:"model"`
    TokensIn  int       `json:"tokens_in"`
    TokensOut int       `json:"tokens_out"`
    Cost      float64   `json:"cost"`        // 美元
    Success   bool      `json:"success"`
    Duration  int       `json:"duration_ms"`
    CreatedAt time.Time `json:"created_at"`
}
```

### 3.3 JWT 认证方案

| 参数 | 值 |
|------|-----|
| 算法 | HS256 |
| Access Token 有效期 | 2 小时 |
| Refresh Token 有效期 | 7 天 |
| Secret 存储 | 环境变量 `JWT_SECRET`（≥32 字符随机串） |
| 载荷 | `{ user_id, email, role, iat, exp }` |

**流程：**

1. 用户登录 → 返回 `{ access_token, refresh_token }`
2. 前端 Bearer Token 请求 API → 中间件校验 JWT
3. 过期 → 前端 Refresh Token 换新 Access Token
4. Refresh Token 过期 → 重新登录

### 3.4 OneAPI 集成

**策略：不改 OneAPI 源码**，通过其内置管理 API（`SYSTEM_ACCESS_TOKEN`）进行配置。

| 操作 | OneAPI API 端点 |
|------|----------------|
| 创建用户（初始额度） | `POST /api/user/` |
| 配置渠道 | `POST /api/channel/` |
| 管理令牌 | `POST /api/token/` |
| 批量生成兑换码 | `POST /api/redemption/` |
| 查询用量 | `GET /api/log/` |

**共享数据卷：** 双实例共享 SQLite 文件（WAL 模式），确保读写一致性。

### 5.2 蓝绿部署

| 组件 | 角色 | 端口 |
|------|------|------|
| HAProxy | 负载均衡器 | 8081（统计） |
| OneAPI Blue | 主实例 | 3001 |
| OneAPI Green | 备实例 | 3002 |

**升级流程：**

1. 更新 Green 容器（拉新镜像 → 重启）
2. HAProxy 健康检查确认 Green 就绪
3. HAProxy weight 切换：Green 权重拉满，Blue 降为 0
4. 退役 Blue 容器（旧版保留为回滚备份）
5. 下次升级角色互换

**回滚三层：**

| 层级 | 动作 | 时间 |
|------|------|------|
| L1 | HAProxy 流量回切到旧版本 | <1s |
| L2 | Docker 容器回滚到旧镜像 | <30s |
| L3 | 数据库/配置恢复到快照 | <5min |

### 5.3 监控告警

| 级别 | 触发条件 | 动作 |
|------|---------|------|
| critical | 渠道完全不可用 | 自动故障切换 + Telegram 告警 |
| warning | 成功率 < 95% | 降低渠道权重 + 记录日志 |
| info | 延迟异常 | 记录 + 日报汇总 |

### 5.4 灾难恢复

| 指标 | 目标 |
|------|------|
| RTO | ≤ 30min |
| RPO | ≤ 1h |
| 备份 | 全量（每日）+ 增量（每小时）|
| 校验 | 远程副本 + SHA256 checksum |

### 5.5 Key 轮换

- **周期：** 90 天自动轮换
- **流程：** 预热验证新 Key → 双 Key 并存 → 删除旧 Key
- **工具：** `scripts/rotate-channel-key.sh`

## 六、数据流详解

### 6.1 用户请求流程

```
用户
  │
  │ POST /v1/chat/completions { model, messages }
  │ Authorization: Bearer sk-xxx
  ▼
Nginx (443/TLS)
  │
  ▼
Go Backend 中间件链:
  1. CORS → 2. 限流 (IP rate limit) → 3. API Key 解析
  │
  ├─ Key 校验失败 → 401 Unauthorized
  │
  ├─ IP 不在白名单 → 403 Forbidden
  │
  ├─ 余额不足 → 402 Payment Required
  │
  └─ 校验通过 →
       │
       ▼
  Go Backend 代理处理器:
  1. 查询用户余额 & 模型定价
  2. 转发到 OneAPI（带 quota 扣除参数）
  3. OneAPI 选择渠道组 → 模型厂商
  4. 获取响应后扣除用户余额
  5. 记录审计日志
  6. 返回 OpenAI 兼容响应
```

### 6.2 支付流程

```
用户点击「充值」
  │
  ▼
Go Backend: POST /api/v1/payment/create
  │
  ├─ 生成订单（金额, 用户ID, 状态 pending）
  │
  ▼
NOWPayments: 创建支付链接
  │
  ▼
用户跳转 NOWPayments 支付页面
  │
  ├─ 选择支付方式 (USDT TRC-20 / BTC / LTC)
  ├─ 扫码支付（或链上转账）
  │
  ▼
NOWPayments Webhook → POST /api/v1/payment/webhook
  │
  ├─ 验证签名（HMAC SHA256）
  ├─ 校验金额（防止篡改）
  ├─ 验证幂等性（防止重复回调）
  │
  ▼
Go Backend 更新订单状态 → confirmed
  │
  ▼
用户余额 += 充值金额（含阶梯赠送）
  │
  ▼
Telegram 通知管理员: 新充值 {email} +${amount}
```

**安全措施：**

1. Webhook 签名验证（HMAC SHA256）
2. 金额校验（回调金额 ≥ 订单金额且阈值 ±5%）
3. 幂等性（订单号去重）
4. 阶梯赠送（充值 $10 送 $1，充值 $50 送 $10 等）

### 6.3 免费福利策略

**约束：** 不自掏腰包送额度（易被薅羊毛），利用厂商免费层。

1. **免费渠道组（OneAPI 侧）：**
   - Gemini 免费层 / 混元免费层 / Groq 免费层 / DeepSeek 免费额度 / 硅基流动
   - 渠道权重均分，避免单厂商被打爆

2. **付费渠道组（OneAPI 侧）：**
   - 现有付费渠道（DeepSeek、智谱 Z.ai、MiMo 等）

3. **促销逻辑（Go Backend 中间件）：**
   - 新用户注册 → 自动获得促销配额（每日 100 次免费调用）
   - 免费调用 → 路由到 OneAPI 免费渠道组
   - 配额耗尽 → 自动切付费渠道组

## 七、安全方案

### 7.1 加密体系

| 场景 | 方案 | 说明 |
|------|------|------|
| API Key 存储 | AES-256-GCM + KDF | 用户 Key 加密存储，server 启动时解密到内存 |
| JWT Secret | 环境变量 | ≥32 字符随机串，`JWT_SECRET` |
| 密码 | bcrypt | cost=12，Golang `golang.org/x/crypto/bcrypt` |
| 数据库 | SQLite 文件级权限 | `chmod 600`，仅容器内可读 |
| Webhook | HMAC SHA256 | NOWPayments 签名验证 |
| HTTPS | TLS 1.3 | Let's Encrypt + Certbot 自动续期 |

### 7.2 API Key 安全

- **格式：** `sk-` 前缀 + 32 字符随机 hex
- **存储：** AES-256-GCM 加密后存入 SQLite，解密到内存
- **吊销：** 即时生效，检查 `status = revoked`
- **IP 限制：** 可选白名单，每个 Key 可绑定最多 10 个 IP

### 7.3 JWT 认证

- **签发：** 登录成功时，服务端签发 access + refresh token
- **验证：** 中间件对每个 `/api/v1/*` 请求校验 Bearer Token
- **刷新：** access_token 过期后，用 refresh_token 换新
- **黑名单：** 登出时将 token jti 加入 Redis 黑名单（如无可跳过）

### 7.4 IP 限制

| 限制 | 阈值 | 动作 |
|------|------|------|
| 注册频率 | 每 IP 每小时 3 次 | 429 Too Many Requests |
| API 调用 | 每 Key 每分钟 60 RPM | 429 并记录 |
| 登录失败 | 每 IP 每分钟 5 次 | 临时封禁 15min |
| 管理 API | 每 IP 每分钟 30 次 | 429 |

## 附录：配置即代码

### 渠道配置 YAML 结构

```yaml
# channels/deepseek.yaml
name: "DeepSeek"
type: "openai"
base_url: "https://api.deepseek.com/v1"
models:
  - "deepseek-chat"
  - "deepseek-reasoner"
keys:
  - id: "primary"
    value: "${DEEPSEEK_API_KEY}"
    priority: 1
    weight: 5
  - id: "secondary"
    value: "${DEEPSEEK_API_KEY_2}"
    priority: 1
    weight: 3
```

通过 GitOps 引擎同步到 OneAPI（`scripts/init.sh` 负责初始化）。
