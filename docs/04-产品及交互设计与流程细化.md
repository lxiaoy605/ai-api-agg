> 品牌：AiFlowHub

## 1. 产品概述

AiFlowHub 是中国模型出海的数字桥梁——将 DeepSeek、GLM、Qwen、MiniMax、Moonshot 等顶尖中国 AI 模型的能力汇成一条统一的全球 API。开发者用一套 OpenAI 兼容接口和一把 API Key，即可调用所有模型。

### 1.1 品牌定位

| 维度 | 内容 |
|------|------|
| **品牌名** | AiFlowHub（全小写） |
| **Tagline** | "Chinese AI Models. One Global API." |
| **Logo** | 五角/六角网络节点图标 + "AiFlowHub" 字标 |
| **视觉风格** | 蓝紫主色调，dark-first 设计，开发者友好的 SaaS 风格 |
| **参考品牌** | Vercel、Stripe、Linear（极简排版/大量留白/无促销感） |
| **禁忌** | ❌ 密集卡片网格 ❌ 红包/积分体系 ❌ 中式/金色调 ❌ MVP/Coming Soon 视觉 |

## 2. 用户角色与场景

### 2.1 目标用户画像

| 画像 | 特征 | 核心诉求 |
|------|------|---------|
| **全球独立开发者** | 1-3 人团队，Solo dev | 快速尝试 · 按量付费 · 零配置 |
| **AI 应用创业者** | 原型开发中 | 一个 API 接所有中国模型 |

### 2.2 核心使用场景

| 场景 | 触发 | 关键路径 |
|------|------|---------|
| **首次体验** | 新用户访问 Landing | 注册 → Dashboard → 创建 Key → 调用 API |

## 4. 交互流程图（关键流程）

### 4.1 完整用户旅程：注册 → 首次 API 调用

```
[New Visitor]
    │
    ├─ 访问 / → 看到 Landing
    │   ├─ Tagline + 模型列表 + 价值主张
    │   └─ 点击 "Get Started"
    │
    ▼
[Sign up] (/register)
    │
    ├─ 表单：Email + Password + Confirm Password
    ├─ 客户端校验：邮箱格式 / 密码 ≥6 位 / 两次一致
    ├─ POST /auth/register
    │   ├─ ✅ 成功 (200) → 存储 token → 跳转 /dashboard
    │   ├─ ❌ 邮箱已注册 → "已注册" + [Sign in] 链接
    │   ├─ ❌ 格式错误 → inline error
    │   └─ ❌ 网络错误 → "Try again" 按钮
    │
    ▼
[Dashboard] (/dashboard) — 首次访问
    │
    ├─ 顶部横幅："Create your first API key to get started"
    └─ 点击 [Create API Key] → 跳转 /api-keys
    │
    ▼
[API Keys] (/api-keys)
    │
    ├─ 空状态：🔑 图标 + 引导文字 + [Create API Key] 按钮
    │
    ▼
[Create Key 弹窗]
    │
    ├─ 输入：Key Name → [Create]
    ├─ POST /api-keys
    ├─ 🔄 Creating… 按钮 spinner
    └─ ✅ 成功 →
       ┌─────────────────────┐
       │ ✓ Key created       │
       │ sk-a1b2c3d4e5…      │
       │ [📋 Copy]            │
       │ ⚠️ 只展示这一次      │
       │        [Done]        │
       └─────────────────────┘
    │
    ▼
[/docs 页面]
    │
    ├─ 复制代码示例
    ├─ 替换为自己的 Key 和 base_url
    └─ curl 调用 /v1/chat/completions
    │
    ▼
[First API Call ✓]
```

### 4.2 登录流程

```
[已注册用户 → /login]
    │
    ├─ middleware 检查：已有 token → 重定向 /dashboard
    ├─ 表单渲染：Email + Password
    ├─ POST /auth/login
    │   ├─ ✅ 200 → 存 token → 跳转 /dashboard（或 ?redirect 路径）
    │   ├─ ❌ 401 → "Invalid email or password."（安全考虑不区分具体字段）
    │   └─ ❌ 500/超时 → 通用错误 + [Try again]
    └─ 底部链接："Don't have an account? Sign up" → /register
```

### 4.3 路由守卫流程

```
middleware.ts 逻辑：

          ┌───────────────────┐
          │   访问某路径        │
          └────────┬──────────┘
                   │
          ┌────────▼──────────┐
          │ 是公开路径?         │
          │ (/, /docs, /models,│
          │  /pricing)         │
          └──┬──────┬─────────┘
       是    │      │   否
             │      │
             │  ┌───▼───────────┐
             │  │ token 存在?    │
             │  └───┬──────┬───┘
             │  是   │      │  否
             │      │      │
             │  ┌───▼──┐ ┌─▼────────────┐
             │  │ 正常 │ │ 重定向 /login │
             │  │ 渲染 │ │ ?redirect=   │
             │  └──────┘ └──────────────┘
             │
          ┌──▼─────────────────────┐
          │ 特殊处理:              │
          │ - 已登录访问 /         │ → 重定向 /dashboard
          │ - 已登录访问 /login    │ → 重定向 /dashboard
          │ - 已登录访问 /register │ → 重定向 /dashboard
          └────────────────────────┘
```

### 4.4 Token 过期处理

```
用户操作中 → API 请求 → 后端返回 401
    │
    ├─ AuthContext 捕获 401
    ├─ 清除 localStorage token
    ├─ 设置 auth state = null
    └─ middleware 无 token → 自动重定向 /login?redirect=<原路径>
```

### 4.5 充值流程（USDT）

```
[/recharge → USDT tab]
    │
    ├─ 金额选择：$5 / $10 / $25 / $50 / $100 + 自定义
    ├─ 链选择：TRC-20 / ERC-20
    ├─ 展示充值地址 + QR 码
    └─ USDT 监听引擎自动检测转账 → 更新余额
```

### 设计决策理由（关键选择）

| 决策 | 理由 |
|------|------|
| **蓝紫主色调**（#3B2FCE→#7B61FF） | 介于技术蓝与创造力紫之间，传达「连接」。竞品（Together AI→橙、Mistral→黑白蓝）均未用蓝紫 |
| **Dark-first** | 开发者 90%+ 时间在 dark-mode IDE，减少视觉跳跃；API 响应/JSON/curl 示例深色背景度更高 |

| **4px 网格** | 所有间距为 4 整数倍，跨组件边界对齐，每 token 有唯一语义 |
| **圆角策略** | 可交互元素圆角小于容器（按钮 8px < 卡片 12px），视觉层级分明 |

## 7. 多语言方案

### 7.1 实现方式

基于 `next-intl`，cookie-based 检测。

| 配置项 | 值 |
|--------|-----|
| 库 | `next-intl` |
| 语言 | EN / RU / TR |
| 默认 | EN |
| localePrefix | `never`（URL 中不显示语言前缀） |
| 检测方式 | Cookie-based（用户选择后持久化到 cookie） |
| 消息文件 | `src/messages/en.json` / `ru.json` / `tr.json` |

### 7.2 路由配置

```typescript
// src/i18n/routing.ts
export const routing = defineRouting({
  locales: ["en", "ru", "tr"],
  defaultLocale: "en",
  localePrefix: "never",
});
```

### 7.3 文案原则（当前产品阶段）

1. **英语优先** — 全球开发者通用语言，目前仅维护英文
2. **简洁直接** — 一句话说明价值，不堆砌
3. **使用 `you` 和 `your`** — 开发者友好
4. **动词动作** — "Create key" 而非 "Key creation"
5. **本地化按需** — 英文为主，RU/TR 翻译后续补充
