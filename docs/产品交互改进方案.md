## 1. 首页重构

### 1.1 当前问题

| 问题 | 描述 |
|------|------|
| 地域隔阂 | "Armenia" 地域名词产生割裂感，面向全球但限定地域 |
| 术语过重 | "MVP Phase", "Coming Soon" 等对终端用户不友好 |
| 无 CTA | 缺少注册/登录/开始使用的入口 |
| 无引导 | 新用户不知道下一步做什么 |
| 导航缺失 | 首页不在 `(main)` route group 内，无侧边栏导航 |

### 1.2 目标用户画像

| 画像 | 特征 | 核心诉求 |
|------|------|---------|
| 全球独立开发者 | 1-3 人团队，Solo dev | 快速尝试 · 按量付费 · 零配置 |
| AI 应用创业者 | 原型开发中 | 一个 API 接所有模型 |
| 中小团队 | 需要多模型能力 | 统一接口 + 统一结算 |

### 1.3 设计语言

- **参照对象**：Vercel、Stripe、Linear
- **风格特点**：大量留白、克制排版、极简 icon、无促销感
- **禁忌**：❌ 密集卡片网格、❌ 红包/积分体系、❌ 促销感文案、❌ 中式红包/黄金色
- **文案风格**：简洁直接，一句话说明价值，相信开发者能自己做判断

### 1.5 用户状态分流

## 2. 全局导航方案

### 2.1 双层导航（Vercel 式）

| 层级 | 适用页面 | 内容 |
|------|---------|------|
| **顶部导航栏**（全局） | 所有页面 | Logo + Models / Docs / Pricing + Sign in / Sign up 或 avatar |
| **侧边栏**（仅 `(main)`） | 控制台页面 | Dashboard / API Keys / Models / Docs / Usage / Recharge |

### 2.2 顶部导航栏

```
未登录:  ⚡ API Hub    Models  Docs  Pricing   [Sign in] [Sign up]
已登录:  ⚡ API Hub    Models  Docs  Pricing   [Avatar ▼ → Console / Sign out]
```

- **左侧**：Logo ⚡ + "API Hub"
- **中部**：产品导航（公开页面）
- **右侧**：未登录 → Sign in / Sign up；已登录 → Avatar dropdown

### 2.3 侧边栏（不变）

侧边栏仅用于 `(main)` route group 内的控制台部分，功能不变。

### 2.4 首页导航

首页（`/`）在根 layout，通过嵌入 TopNav 组件获得导航。

## 3. 用户交互流程

### 3.1 注册 → 首次 API 调用

```
[New visitor]
    │  → / → See landing, click "Get Started"
    ▼
Sign up (email + password)
    │  → Auto-login, redirect to /dashboard
    ▼
Dashboard (first visit)
    │  → Slim welcome banner: "Create your first API key to get started"
    │  → Action button: "Create API Key"
    ▼
/api-keys page (first visit)
    │  → Empty state with prominent CTA
    │  → Create key → name it → copy once
    ▼
/docs page
    │  → Copy code snippet
    │  → Replace with your key and base_url
    ▼
First API call ✓
```

### 3.2 关键引导节点

| 节点 | 引导方式 |
|------|---------|
| 新用户首次进入 Dashboard | 简短的顶部横幅 + 单按钮 CTA |
| API Keys 为空 | 大号 empty state + "Create Key" 按钮 |
| 创建 Key 后 | 弹窗展示 Key 一次 + 复制引导 + 安全提示 |
| 余额不足 | 返回具体错误码 + 链接到充值页 |
| 模型不可用 | 错误提示 + 建议切换其他模型 |

### 3.3 引导原则

- **极简引导**：状态本身即引导。空状态 = 引导。不额外插入冗余弹窗。
- **相信开发者**：不做弹窗式「欢迎教程点击下一步」，让用户自然探索。
- **错误即提示**：错误信息本身就是最好的引导。
