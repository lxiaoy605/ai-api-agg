   └──────────┘   └──────────┘
   ┌──────────┐   ┌──────────┐

**流量路径**：
```
用户请求 → HTTPS(:443) → Nginx → HTTP → HAProxy(:8080)
  ├── OneAPI Blue (:3001) / Green (:3002) → 上游模型源
  └── Backend Blue (:8082) / Green (:8083) → SQLite

Prometheus(:9090) ─→ Backend /metrics
                 ─→ Blackbox(:9115) ─→ 各端点探针
                 └→ 告警规则 → Alertmanager(:9093) → Telegram
```

## 四、蓝绿部署方案

### 4.1 架构

维护两套独立池（OneAPI 池 + Backend 池），HAProxy 按权重分发流量。

```
池: oneapi       Blue :3001 ← weight=100(default) → Green :3002
池: backend      Blue :8082 ← weight=100(default) → Green :8083
```

### 4.2 切换模式

| 模式 | 参数 | 停机时间 | 场景 |
|------|------|---------|------|
| 完全切换 | `--mode instant` | 零停机 | 升级/维护/故障转移 |
| 灰度迁移 | `--mode gradual --weight N` | 零停机 | 新版本灰度上线 |

### 4.3 核心命令

```bash
# 查看当前状态
./scripts/bluegreen-switch.sh status

# 完全切换到 Green（OneAPI 池）
./scripts/bluegreen-switch.sh --target green --mode instant

# 灰度 30% 流量到 Green（Backend 池）
./scripts/bluegreen-switch.sh --pool backend --target green --mode gradual --weight 30

# 紧急回滚
./scripts/bluegreen-switch.sh rollback
```

### 4.4 一键部署蓝绿环境

```bash
# 前置条件
cp docker/.env.example docker/.env
cp docker/oneapi/.env.example docker/oneapi/.env
# 编辑 .env 填入实际值

# 一键部署
./scripts/bluegreen-deploy.sh

# 查看状态
./scripts/bluegreen-deploy.sh --status
```

### 4.5 三层回滚

| 层级 | 触发条件 | 恢复时间 | 影响 |
|------|---------|---------|------|
| L1 流量回滚 | 新版错误/人工触发 | 秒级 | 零停机 |
| L2 容器回滚 | L1 后旧版不可用 | 分钟级 | 短暂中断 |
| L3 数据回滚 | 数据库迁移失败 | 分钟级 | 数据回退到备份点 |

```bash
# L1 流量回滚
./scripts/rollback.sh --layer 1 --auto

# L3 数据恢复（从指定备份）
./scripts/rollback.sh --layer 3 --backup backups/full/20260528_120000.tar.gz
```

## 五、高可用方案（Keepalived + HAProxy）

### 5.1 架构

```
          客户端
            │
     ┌──────▼──────┐
     │  虚拟 IP     │  ← Keepalived 管理的浮游 IP
     │  10.0.0.100 │
     └──────┬──────┘
            │
   ┌────────┼────────┐
   ▼                 ▼
┌──────────┐    ┌──────────┐
│ VPS #1   │    │ VPS #2   │
│ MASTER   │◄──►│ BACKUP   │  VRRP 心跳
│ priority │    │ priority │
│   100    │    │    50    │
└────┬─────┘    └────┬─────┘
     │               │
  HAProxy         HAProxy
     │               │
  OneAPI          OneAPI
  Blue/Green      Blue/Green
```

### 5.2 当前状态

## 六、监控体系

### 6.1 组件清单

| 组件 | 端口 | 角色 |
|------|:----:|------|
| Prometheus | 9090 | 指标采集+存储+告警评估 |
| Grafana | 3030 | 可视化仪表盘（预配 15 面板） |
| Alertmanager | 9093 | 告警去重+路由+通知 |
| Blackbox Exporter | 9115 | 外部 HTTP/HTTPS 探针 |
| Backend `/metrics` | 8082/8083 | Prometheus 原生指标端点 |

### 6.2 告警规则（12 条）

| 级别 | 规则 | 触发条件 | 通知 |
|:----:|------|---------|------|
| 🔴 紧急 | `TargetIsDown` | 目标不可达 > 15s | Telegram Ops |
| 🔴 紧急 | `HighErrorRate` | 5xx > 5% 持续 5m | Telegram Ops |
| 🔴 紧急 | `DiskSpaceCritical` | 磁盘 > 95% | Telegram Ops |
| 🟡 警告 | `HighLatency` | P95 > 5s 持续 5m | Telegram Ops |
| 🟡 警告 | `LowBalance` | 上游余额 < $20+3天用量 | Telegram Ops |
| 🟡 警告 | `UpstreamUnhealthy` | 某渠道错误 > 20% 持续 5m | Telegram Ops |
| 🟡 警告 | `BackupFailed` | 备份失败 > 1 次 | Telegram Ops |
| 🟡 警告 | `DiskSpaceLow` | 磁盘 > 85% | Telegram Ops |
| 🟡 警告 | `HighCPUUsage` / `MemoryUsageHigh` | 资源紧张 | Telegram Ops |
| 🟡 警告 | `ContainerRestarted` | 容器重启 > 1 次/5m | Telegram Ops |
| 🟡 警告 | `ReconcileMismatch` | 支付对账差异 > 3 笔 | Telegram Ops |

### 6.3 告警抑制

| 主告警 | 抑制的衍生告警 | 原因 |
|--------|---------------|------|
| `TargetIsDown` (OneAPI) | `UpstreamUnhealthy` (同一目标) | 非上游问题 |
| `TargetIsDown` (某实例) | `HighErrorRate`, `HighLatency` | 实例整体不可用 |
| `DiskSpaceCritical` | `DiskSpaceLow` | 95% 已覆盖 85% 信号 |

### 6.4 管理后台访问

| 后台 | 地址 | 认证 |
|------|------|------|
| Grafana | `http://<主机IP>:3030` | `admin` / `GRAFANA_ADMIN_PASSWORD` |
| Prometheus | `http://<主机IP>:9090/alerts` | 无认证 |
| Alertmanager | `http://<主机IP>:9093` | 无认证 |
| OneAPI 管理 | `http://localhost:3001` (Blue) | `root` / `123456` ⚠️ 改密码 |
| HAProxy 统计 | `http://localhost:8081/stats` | `admin` / `admin` ⚠️ 改密码 |

## 七、SSL 证书方案

### 7.1 方案

- **工具**：Let's Encrypt (Certbot)
- **方式**：Webroot 验证（复用 Nginx 的 `/var/www/certbot`）
- **自动续期**：系统 cron `certbot renew`，Nginx 容器通过 bind mount 共享 `/etc/letsencrypt`

### 7.2 首次获取

```bash
# DNS 解析生效后执行
docker compose -f stack/docker-compose.yml run --rm certbot \
  certonly --webroot -w /var/www/certbot \
  -d aiflowhub.ai -d www.aiflowhub.ai
```

### 7.3 域名绑定

| 服务 | 线上域名 | 说明 |
|------|---------|------|
| 主站 + API | `aiflowhub.ai` | Nginx 反代 |
| HAProxy 统计 | `stats.aiflowhub.ai`（可选） | 加 IP 白名单 |
| Grafana | `grafana.aiflowhub.ai`（可选） | 加 IP 白名单 |
| OneAPI 管理 | 不暴露公网 | SSH 隧道/内网 |

### 7.4 证书检查

```bash
# 检查到期时间
openssl x509 -in /etc/letsencrypt/live/aiflowhub.ai/fullchain.pem -noout -dates

# 自动续期日志
tail -20 /var/log/letsencrypt/letsencrypt.log
```

## 十一、部署注意事项

### 不！能！动！的！配！置！

| 项目 | 规则 | 原因 |
|------|------|------|
| 前端 Base Image | **`node:22`**，非 alpine | 2026-05-30 alpine 导致 `@parcel/watcher` musl 兼容问题 |
| `next.config.js` | **不加** `output: "standalone"` | standalone 模式 `.next/standalone/.next/static/` 不自动生成 |
| Compose frontend | `ports: 3000:3000`（非 `expose`） | 外部须访问 3000 端口 |
| Compose frontend | `HOSTNAME=0.0.0.0` | 必须设否则外网不可达 |
| Compose 项目目录 | 只用 `stack/docker-compose.yml` | `compose/` 是旧版存档，不可混用 |

### 通用原则
